\section{Use of Generative AI}
\label{sec:decl-ai}

In this work I used the generative AI assistant \emph{Claude}, model family Claude Opus, published by Anthropic (\url{https://www.anthropic.com}) and accessed through the Claude Code tool (\url{https://claude.com/claude-code}), throughout the project. Two auxiliary tools were called from within it: PapersFlow, for bibliographic look-up and citation verification, and the Brave Search API, for web search. This section discloses that use against the research-subtask list of the ICLR~2027 author guidelines, as the MRes regulations require.

I used generative AI tools to provide feedback on research methodology and experiments and to help refine them; every design was adopted on my decision. I used them to implement methods: the code in the repository was written with the assistant to my specifications, then run, inspected and debugged by me. I used them to clean and reformat datasets; to propose and refine hypotheses, each kept or discarded by me; to help develop the conceptual framework, above all the distinction between marginal realism and informativeness fidelity; and to formulate mathematical claims and their short derivations, each checked numerically by me. Results were interpreted in dialogue with the assistant; the final interpretation, and every claim in this thesis, is mine. I also used generative AI tools to write and edit software code, to create figures and tables from the saved result files, to plan and draft parts of this thesis, which I read, edited and approved, and to search and summarise the literature. I did not use generative AI tools to generate synthetic datasets: every synthetic ECG analysed here comes from the published MedalCare-XL dataset, and no AI-generated data of any kind was used. Translation and qualitative or thematic data analysis are not applicable to this work.

I have reviewed all AI-assisted work. Every quantitative result was produced by scripts that I ran, archived at the tagged commit named in Section~\ref{sec:decl-data}; the central results were independently re-implemented as a check, and every number in the text was traced back to the result file that produced it. Every reference was verified against a bibliographic database before it was cited. I take responsibility for the final content of this work, including all text, claims and artefacts produced with the aid of generative AI.

\section{Ethical Considerations}
\label{sec:decl-ethics}

This project did not require ethics approval and none was sought. It uses no data collected by me and involves no human participants. The two datasets are PTB-XL, a publicly released and de-identified clinical ECG dataset distributed through PhysioNet under its own institutional ethics arrangements, and MedalCare-XL, a fully synthetic dataset that contains no data from any real person. No attempt at re-identification was made, and no record-level clinical data leave the analysis environment. No formal ethics review was filed at any stage, because the data situation was clear from the outset.

The ethical risks I considered concern the use of the results rather than of the data. First, a negative sim-to-real result can be over-read as ``digital twins are not useful''. The thesis argues the opposite, that a synthetic cohort should be audited for the information a task needs before it is used, and the text is written to resist that misreading. Second, the audit itself could be misused to select only the channels on which a simulator looks faithful, and so over-sell it. The thesis therefore reports the full per-feature map and the failed repair arms alongside the one that reached parity. Third, any model or readout described here is a research artefact and is not intended for, or validated for, clinical use. The broader impact I hope for is a safer validation practice for synthetic-data pipelines in cardiology.

\section{Sustainability}
\label{sec:decl-sustain}

The computational footprint of this project was kept small by design. I reused the publicly available pre-trained ECGFounder model rather than pre-training one. Every fine-tuning run adapted a frozen backbone with lightweight adapters and a small head, for at most 30 epochs. The entire analysis stage, from feature extraction to the repair experiments, runs on CPU from cached latent representations, so no GPU time was spent on evaluation. No large hyper-parameter sweeps were run, and an explicit freeze at the end of the experimental phase prevented redundant re-runs. All training was performed on a single consumer GPU (NVIDIA GeForce RTX~5080, 16\,GB) in a personal workstation. No run logged its wall-clock time, so I bounded each run by the modification-time span of its output directory. The twenty fine-tuning runs that survive on disk account for roughly 9~GPU-hours in total; latent export and the lead-permutation inference sweep add a further 3--4. Allowing the same again for early exploratory runs whose outputs were later deleted, I estimate the project's total GPU usage at roughly 25~GPU-hours, with 40 as an upper estimate. That is of the order of 10\,kWh of electricity and 1--2\,kg~CO$_2$e at typical UK grid intensity, an order-of-magnitude statement rather than a measurement. \tracenote{thesis_writeup/notes/gpu_hours_estimate.md}
